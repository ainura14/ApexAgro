# Контракты API (BE3-08)

Один файл на модуль: `api/<module>.yaml` (OpenAPI 3.1). Имя файла = имя модуля = группа springdoc
(`springdoc.group-configs` в `application.yml`).

## Порядок работы (contract-first)
1. Владелец модуля пишет/меняет `api/<module>.yaml` и открывает PR. Ревью — FE + владелец модуля (CODEOWNERS).
2. После согласования реализует эндпоинты.
3. `OpenApiContractTest` сравнивает код с контрактом: набор операций, наличие тела запроса, коды 2xx.
   Модуль с эндпоинтами без файла здесь — тоже ошибка. Любое расхождение валит `./gradlew test` и CI.
4. В CI дополнительно: `openapi-diff` (глубокое сравнение схем) и генерация TS-клиента для FE (артефакт `ts-client`).

## Общие правила
- Базовый путь `/api/v1`.
- Ошибки — `application/problem+json`, схема `ProblemDetail` (поля `code`, `traceId`, `errors[]`).
  Стандартные ответы 400/401/403/404/429/500 с примерами springdoc добавляет сам; в контракте их можно не описывать.
- Деньги — строка с 2 знаками (`"1250.00"`), количество — строка с 3 знаками (`"12.500"`), даты — ISO 8601 UTC.
- Страница: `{ items, page, size, total }`, `page` с нуля, `size` ≤ 100.

## Посмотреть, что генерирует код
- Swagger UI: http://localhost:8080/swagger-ui.html
- Спецификация модуля: http://localhost:8080/v3/api-docs/<module> (или `.yaml`)
