# 0001. Модульный монолит на Spring Modulith, схема БД на модуль

- Статус: Принято
- Дата: 2026-10-24

## Контекст
Команда из трёх backend-разработчиков, MVP за 10 спринтов. Нужна скорость одного приложения и при этом
границы, которые позволят позже вынести модуль в отдельный сервис.

## Решение
- Одно приложение Spring Boot. Модуль = пакет первого уровня под `com.apexagro`.
- Публичный API модуля — в корне пакета (`XxxApi`, DTO, события), реализация — в `internal/`.
- У каждого модуля своя схема PostgreSQL; связи между схемами — только по id, без FK.
- Взаимодействие модулей: синхронно через `XxxApi`, асинхронно через события (ADR-0004).
- Границы проверяются в CI: `ModularityTests` (Spring Modulith), `ArchitectureRulesTests` (ArchUnit),
  `MigrationBoundaryTest` (сканер SQL).

## Последствия
- Нельзя сделать JOIN между схемами — данные чужого модуля берутся через его API.
- Нарушение границы ломает сборку, а не обнаруживается на ревью.
